The motivation — one squeeze, two failures

Joint tc768 fails twice at once

Halving the per-token channels 1536→768 in one training run tangles two independent problems. A single linear 1536→768 layer shouldn't cost much — yet the trained joint squeeze plateaus 7× above the uncompressed code.

Best Eval/Loss ever reached (KITTI + Occ3D-nuScenes, held out; all pre-1ecb17c). Stage 1 is the uncompressed 1536 source — and its SIGReg even edges out the plain dtok64, so isotropy costs no recon.

Failure 1 · optimization

Can't find the linear subspace

Trained joint tc768 plateaus 7× above the uncompressed code (linear 0.0796 → 0.0335 with SIGReg). A single linear layer shouldn't cost that — the optimizer never locates the good 768-d subspace decoder gradients alone should reveal.

Failure 2 · geometry

The code that survives collapses

Participation ratio falls to 17.6/768 with no regularizer; SIGReg lifts it to 173, still ~22% of budget. A rank-collapsed latent is a poor target for the downstream flow.

The idea: untangle them. Fix the geometry first at full width (Stage 1), then give a dedicated bottleneck a stationary target so it can hunt the subspace on its own (Stage 2).

The first run broke — and the fix was one line

Round-trip to the raw code, not the normed one

Run 1 (JZ 478759) matched loss ② against the post-LayerNorm tensor. Fidelity got monotonically worse every epoch — a textbook scale-collapse, hidden inside a falling loss.

The trap · scale collapse
  • loss② was homogeneous degree 1 in the trainable pre-norm gain γ — so shrinking γ lowers it for free.
  • .detach() on the target removed the one gradient that would have resisted the shrink.
  • Measured across one epoch: γ 1.0 → 0.46; ~70% of the loss② drop was fake scale, not fidelity.
  • The frozen decoder was trained on the raw code, so it got progressively mis-scaled input → eval recon rose 0.031 → 0.033 → 0.038.
The fix · deltatok_trainer.py:363
# round-trip target = the code the frozen decoder was trained on z_pre = pre_bottleneck_norm(z) # post-norm ✗ z_pre = z # raw, pre-norm ✓
Now the target is constant under the frozen encoder, so no trainable param can shrink it — and it matches what the decoder actually expects. Both failures die at once. The rawtgt tag in the run name marks the fixed arm.
Result of the one-line change
monotone worsening → monotone convergence

Why it survived

The round-trip loss reconstructs the raw 1536-code (PR ~700) through 768 dims. Faithfully round-tripping a high-rank target forces z_proj_down to keep its dominant directions, so the code inherits the spread. The broken post-norm run (PR ~150) is the control: corrupt the target, lose the spread too.

Honest caveat: the loss doesn't guarantee this. With SIGReg off it's invariant under any A∈GL(768) (down→A·down, up→up·A⁻¹) — spread is a gauge it can't see. From a near-isometric init, gradient descent simply never drifts there. ZPartRank: Stage 1 @ ep40 (frozen source), Stage 2 @ ep20.

Reading it — implicit preservation, and the ceiling

Kept by the optimization, not the loss

Both axes landed — so what's left is why the spread survived a gauge-free loss, and where it stops.

The mechanism

High-rank target ⇒ spread-preserving projection

  • Round-tripping a PR-~700 code through 768 dims is only solvable if z_proj_down keeps the top directions — so it does.
  • From a near-isometric init, GD finds that solution, not a gauge-collapsed twin at equal loss.
  • Confirmed by the control: the broken post-norm run corrupted the target and collapsed to PR ~150.
The ceiling · optional push

~half the budget — SIGReg's universal floor

  • 47–61% utilization is the same ~50% isotropy asymptote SIGReg hits everywhere, not a bottleneck-specific cost.
  • To push past half: SIGReg on the frozen-encoder bottleneck (a pure conditioner on Wdown) — one un-zeroed weight.
  • Or fold analytic whitening A=Σ−1/2 post-hoc, output-preserving. Both are polish now, not a fix.
