What does the channel budget actually buy?

One recipe, one knob: target_channels at 128 / 256 / 512 / 768 / 1536, everything else held fixed (dtok64 · nozn · maxgap9 · vpt1to2 · sigreg 0.005 · pool8192, ns = 2·tc). Reconstruction improves with every doubling — but the return collapses past tc512, and the code's effective rank stops growing entirely.

Why tc1536 is off the curve

Square projection = no channel squeeze

The tokenizer's hidden width is 1536 (hidden_size = backbone.embed_dim, deltatok_shared.py:486). At tc1536 the linear z_proj_down is 1536→1536 and can represent the identity, so the only compression left is the 64-token axis. Treat it as the ceiling the compressed arms are chasing.

The code stops using the channels you give it

Effective rank climbs from 81 to 134 across 128→512, then stops dead. tc768 uses exactly as many directions as tc512 while paying 1.5× the storage. Utilization falls monotonically: 63% → 17%.

The saturation

SIGReg at 0.005 fills 63% of a 128-d code but only 17% of a 768-d one. Scaling ns with width kept the per-dimension pressure matched and still did not help — the ceiling is ~134 directions, not a fixed fraction. KITTI agrees: 79 → 101 → 123 → 136.

It lines up with fidelity. Recon flattens exactly where the effective rank does, between 512 and 768. The extra channels are not being used, so they cannot reconstruct anything. tc1536's 225 is again the no-bottleneck case — 13% of 1536, the lowest utilization in the sweep.

Takeaways — what the sweep settles, and what it doesn't

tc512 is the knee

1
Pick tc512. It captures the whole usable return of the channel axis — −18% recon vs tc128 at matched epoch 47 — and going to 768 adds 1.5% for 50% more latent storage. Best compressed AR pointmap in the sweep: PredVsOrig_AR = 0.5437 (nuScenes).
2
Spread is the binding constraint, not width. Effective rank saturates at ~134 directions — tc512 and tc768 land on the identical ZPartRank. Recon flattens at exactly the same place. Widening the code past 512 adds channels the optimizer never populates.
3
Pointmap follows recon — against the untokenized pointmap. tc128→tc512 moves LossRecon_AR −19.4% and LossPointmap_PredVsOrig_AR −18.8% (0.660 → 0.536, last-10-epoch means). Measured against ground truth instead, the same gain shows as −2.4%: DA3's own OrigVsGT = 3.3217 is 94% of that number.
4
SIGReg 0.005 does not scale with width. Utilization drops 63% → 17% across the sweep even though ns = 2·tc keeps the per-dimension pressure matched. The next lever is the isotropy driver, not the budget.
5
The ceiling is still 2.4× away. Uncompressed tc1536 reaches 0.0141 against tc768's 0.0338. A square z_proj_down is no bottleneck at all, so this is the honest headroom a channel squeeze is giving up.
