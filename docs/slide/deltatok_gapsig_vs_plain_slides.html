Verdict — what the knob actually did

Drop gapsig. Plain SIGReg reconstructs better.

1
The result is unanimous. Round-trip loss is 6.5–13.9% worse for gapsig across Depth, Pointmap, Raymap on both KITTI and nuScenes. No metric favours it.
2
The comparison is fair. The teacher ceiling (OrigVsGT) is bit-identical, so both arms see the same eval. gapsig trails from early on, not just at the end.
3
End-to-end masks it. On nuScenes, PredVsGT moves only +0.5% — the teacher's error dwarfs the tokenizer's. Judge tokenizer changes on PredVsOrig, not PredVsGT.
4
Likely cause. Dividing z/√gap shrinks large-gap codes before the CF test, so SIGReg pins the rescaled code to N(0,I) and lets raw large-gap z drift off-distribution. Plain SIGReg regularises the code the decoder actually reads.

1
SIGReg now polices the wrong code. Dividing z/√gap means the CF test certifies the normalized code, not the raw z the decoder reads.
2
The test gets weaker. Its pool is a soft (w=0.005), stale 8192-row FIFO now spanning a mixture of scales (Var 1→9). That is a poor isotropy driver — so the raw code spreads over fewer dims and its scale balloons.
3
Rank is capacity. DeltaTok recon tracks usable rank at corr −0.997 (tc-width sweep). ~20% fewer usable dims ⇒ the 6–14% worse reconstruction.
And the premise is shaky. Var ∝ gap assumes feature deltas diffuse like Brownian motion. Bounded, frame-correlated driving-scene features don't — so √gap over-inflates large-gap codes for no information gain. (per-gap magnitude unverified)
