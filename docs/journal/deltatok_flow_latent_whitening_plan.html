RAE-style per-channel whitening of DeltaTok flow latents

DeltaTok's final LayerNorm normalizes rows (per token, across channels). The flow's isotropic noise needs normalized columns (per channel, across the dataset). Add the missing axis, gated by a config flag, and produce the ablation the RAE paper skips.

Context — why

The frozen tokenizer's last op is nn.LayerNorm(cfg.hidden_size, eps, elementwise_affine=False) (occrae/deltatok_trainer.py:138). norm_affine=false removes the learned scale, so the intuition was "the latents are normalized". A pdb probe on x_spatial said otherwise:

(Pdb) x_spatial.max()   →  tensor(36.7141)
(Pdb) x_spatial.min()   →  tensor(-7.1765)

Nothing is broken — this is what LayerNorm actually guarantees. Lay the delta tokens out as a matrix with rows = tokens (M = B·(T-1)·N·K) and columns = channels (C):

  • LayerNorm normalizes each row, independently: mean 0, RMS 1 along that row's C channels. That is the whole operation — it never looks at another row.
  • The only bound on an element is |x_i| ≤ sqrt(C-1), reached when one channel holds the token's entire energy. With C in the thousands that ceiling is in the tens. That is the 36.7.
  • Columns are completely unconstrained. Every row can have RMS 1 while column 7 has std 30 and column 900 has std 0.01 — the classic massive activation pattern, and DeltaTok is built on DINOv3ViTConfig/DINOv3ViTLayer (deltatok_trainer.py:93-99), where it is well documented.
    Measured: the pattern is real but appears in the mean, not the std — c=527 is a constant 34.38 carrying 76.8% of the energy, while stds only span 0.27–2.46.

Verified as a tautology, not evidence. A first probe reshaped to x_spatial.reshape(-1, 64) and got per-column mean ~1e-9, std ~1. That measured the wrong axis: x_spatial is (B, C, T-1, N, K), so 64 is K (num_delta_tokens, the dtok64 in the run name), not C. Reducing over axis 0 sweeps the channel axis, and LayerNorm forces Σ_c x = 0 exactly — so that result is structurally 0 regardless of channel skew. The real probe puts channels last: x_spatial.movedim(1,-1).reshape(-1, C), then .std(0).

Why the flow cares

flow_noising (occrae/deltatok_flow_trainer.py:428-460) builds z_t = t·x + (1-t)·e with isotropic e ~ N(0, I). So the per-channel SNR is:

SNR_c(t) = t · std_c / (1 - t)

A channel with std_c = 30 stays legible at near-pure noise; one with std_c = 0.05 is buried at near-clean. One t means a different effective noise level in every dimension, and the quadratic loss is dominated by the high-std channels while the low-std ones are never meaningfully trained. LayerNorm pins the average of std_c² to ~1 but leaves the spread free.

Measured — the effect is real but modest. Std spans 0.2685–2.4633, so the quadratic loss weights channels by std_c² over a 82.7× range, with 87.2% of channels below std 0.5. That is a genuine per-channel SNR mismatch, but nothing is buried: the low tail bottoms out at 0.27, not 0.01. The dominant structure is the mean (78.7% of energy), which this section does not model at all — a constant offset is a bias term the flow learns almost immediately, so it inflates the apparent loss scale without ever being hard.

This is exactly the step the RAE paper describes and never ablates: "RAE secretly whitens all dimensions in their code using training dataset statistics, normalizing each dimension to std=1. It may be important for a consistent signal-to-noise ratio schedule across dimensions, but the effect of this whitening step is never ablated."

Constraints

  • Tokenizer stays frozen. Whitening is an invertible affine on its output — no tokenizer retrain.
  • Default is a no-op so the existing 50k ckpt and every current run stay loadable.
  • Diagonal (per-channel mean/std) only, matching RAE. Full ZCA/PCA whitening is out of scope.
  • Never run code locally. The user syncs files manually — ask before submitting; never scp/rsync.

Phase 1 — Wire whitening

occrae/deltatok_shared.py:232-240. The pair is @staticmethod today, but every call site already goes through self./trainer. (deltatok_flow_trainer.py:546, :719, :738; eval_deltatok_flow_t_bins.py:218) — so converting to instance methods needs no call-site changes.

def _z_to_flow_latent(self, z):          # (B, T-1, N, K, C) -> (B, C, T-1, N, K)
    m = getattr(self, "_whiten_mean", None)          # None -> identity
    if m is not None:
        z = (z - m) / self._whiten_std               # per-channel, broadcasts on last dim
    return z.permute(0, 4, 1, 2, 3).contiguous()

def _flow_latent_to_z(self, x):          # (B, C, T-1, N, K) -> (B, T-1, N, K, C)
    z = x.permute(0, 2, 3, 4, 1).contiguous()
    m = getattr(self, "_whiten_mean", None)
    if m is not None:
        z = z * self._whiten_std + m
    return z
  • Whiten in z-space (channels last → natural (C,) broadcast), un-whiten after the permute back.
  • getattr(..., None) keeps DeltaTokTrainer safe — it hosts the mixin but never calls the pair.
  • _load_whiten_stats() helper on the mixin, called from the flow trainer __init__ after _build_deltatok (:108). std.clamp_min(eps) at load so a dead channel can't amplify pure noise.
  • New config key model.whiten_stats: null in configs/train_deltatok_flow.yaml.
  • Save the stats path into the flow ckpt for provenance; print it at load.

Why the pair is airtight. Context pinning at :729 uses x_spatial (whitened), gen comes out whitened, and :738 un-whitens → z_hat returns to the original z-space. So _rollout_from_z (:746) and MSEToken (:803, z_hat vs z) stay in the original space and remain directly comparable to the baseline's 0.2816. No other edits needed.

LossFlow IS comparable — via a measured 4.70× factor. The plan said it was not, and stopped there. It is not comparable raw, but the conversion is exactly computable from the Phase 0 stats, which turns the discarded metric into the sharpest one.

A per-channel mean is a bias term: the flow fits it almost instantly, so it costs ~no error at convergence. The irreducible part of the target is therefore what remains after the means are known — and whitening removes exactly that removable part:

unwhitened irreducible = (1/C)Σ s_c²        = 0.2126
whitened   irreducible = (1/C)Σ 1²          = 1.0
predicted LossFlow ratio = 1.0 / 0.2126     = 4.70×

Observed at matched epoch 0: 5.3952 / 1.1428 = 4.72× — the prediction confirmed to 0.4%. So at equal stage the two models have indistinguishable skill; the whole gap is the rescale.

It composes config without _RUN_DEFAULTS, so without an explicit --cfg model.whiten_stats=<path> the pair is the identity: the ViT samples in whitened space and z_hat (:297) is treated as original-space deltas → garbage rollouts, no error raised (unlike an arch mismatch, which strict=True catches).

  • The ablation bundles two interventions. Mean-centering (78.7% of energy) and std-normalization (21.3%) cannot be attributed apart without a mean-only third arm.

Adjacent lever — timestep shift not started

Same failure family (schedule mismatched to this latent), different axis: whitening fixes the per-channel SNR spread; the RAE/SD3 shift fixes the global noise level for the latent's dimensionality. RAE calls it "significant" and it costs one config key — for a logit-normal schedule the shift is a constant offset in logit space, i.e. exactly model.mu (logit(t_m) = logit(t_n) + log α, α=√(m/n)).

But RAE's α is dimensionally incoherent — do not copy the formula. SD3 defines n = H·W pixels; RAE ships time_dist_shift_dim: 196608 # 16*16*768 against time_dist_shift_base: 4096 — scalars ÷ tokens, inflating α by ~√768. The tell: assert time_dist_shift >= 1.0, while both coherent readings give α<1 and would crash it (tokens/tokens 256/4096 → 0.25; scalars/scalars 196,608/262,144 → 0.87). Only the incoherent reading yields the noisier shift they want — it is a tuned constant with a √(m/n) story wrapped around it.

For us: tokens/tokens → mu +0.33; scalars/scalars → mu −1.26; RAE-style → mu −3.34. The conventions disagree on the sign. Also our m is not fixed (T−1 varies), and Phase 0 says our effective rank is far below 1536, so a raw scalar count overstates m on RAE's own logic. Treat mu as an empirical knob (sweep −0.7 / −1.3 / −2.0).
