Plan — native-K DeltaTok flow matching, run on K=32

Make the whole delta-token path work with any K (K=1 = special case), then flow-match on the best tokenizer of the num_delta_tokens sweep (K=32) on Jean Zay.

Target Jean Zay H100 Branch revert Recipe delta_ctx + global + camera_embed (kept) Latent (B, C, T-1, N, K)

Context — why

The ablation shows more delta tokens K per camera per transition monotonically lower pointmap loss: K=1 → 2.66, K=8 → 0.74, K=16 → 0.47, K=32 → 0.36 (KITTI PredVsOrig) — ~7× better than K=1. dtok32 is the best tokenizer of the sweep.

The tokenizer already supports configurable K, but the flow-matching trainer only works at K=1 — the K axis is squeezed away when K==1 and the flow code hardcodes the resulting 4D layout with unsqueeze(-1)/squeeze(-1). Goal: make the delta-token path native to any K (no K=1 special-casing anywhere), then run flow matching on the K=32 tokenizer.

Design principle — K is a first-class axis everywhere

  • Delta tokens z are always 5D (B, T-1, N, K, C); per-transition z_t always 4D (M, N, K, C). Flow latent always (B, C, T-1, N, K). K=1 ⇒ trailing axis size 1, numerically identical to today.
  • Remove all K=1 squeeze/unsqueeze at the source (not downstream shims).
  • The flow Transformer is renamed to speak (B, C, T, N, K) directly (N = cameras, K = delta tokens), replacing the generic (B,C,T,H,W) labels — a scoped, behavior-preserving relabel.
  • ref_spatial_size=(1, K) stays a 2-tuple: already "1-D over K, broadcast across N" (K→K identity, 1→N replication); the 2-D interpolation machinery must stay because eval_occ_rae.py uses it as a real image grid. No literal 1-D collapse.
Flow recipe (kept, per user): delta_ctx + global + camera_embed=true.
  • global → one attention over all t·S tokens, S = N·K.
  • delta_ctx (n_ctx=1) → first transition's delta tokens are the clean in-seq context (T-1 axis, K-agnostic); no cross-attn (cross_dim=None).
  • load-bearing camera_embed=true currently indexes per flat slot arange(S) and asserts S ≤ max_cameras(32) — breaks at K=32 (S = N·K). Reworked to native-K: index by camera = s // K, assert on N. Change #3(b) below.

Verified facts (from exploration)

  • _encode_pair_deltas (deltatok_shared.py:207-212) builds 5D and only squeezes at the end when K==1. DeltaTokModule.encode always returns 4D (M,N,K,C).
  • _rollout_from_z is already native-K (no dim() assert / no squeeze; z_t = z_seq[:,t] → 4D straight to decode).
  • DeltaTokModule.decode: for K=1, old 3D input (M,N,C)→unsqueeze(2) is bit-for-bit identical to passing 4D (M,N,1,C) — so the 3D branch is dead once every caller passes 4D.
  • Tokenizer-trainer consumers are safe under always-5D: rollout passes z straight through, teacher-forced forward bypasses _encode_pair_deltas, and all _AR/_PredVsOrig metrics consume x_hat, never z.
  • Cross-attn is per-slot, hard check n_cond == S — with S=N·K, _build_cross_cond must emit N·K slots. Only reached in cond_mode=cross; the chosen delta_ctx never builds cross_cond.
  • Camera-embed (efficient_transformer.py:220-221, 395-399): nn.Embedding(max_cameras=32, D), per-slot arange(S), assert S ≤ 32 — the one path that breaks at K=32. camera_rope is disallowed in global mode at construction (:191-193), so it is not exercised.
  • K is read only from config (num_delta_tokens, default 1); the tokenizer loads strict=True → flow config must set num_delta_tokens=32 or the z_embed load crashes.
  • flow_euler_sample, _sample_noise, flow_noising, flow_loss are shape-generic — no change.
  • Second Transformer caller: eval_occ_rae.py passes ref_spatial_size=(patch_h, patch_w) as a genuine image grid and relies on the 2-D bicubic interpolation → the N/K rename is functionally inert there but semantically mislabels it (add a comment); do not collapse to literal 1-D.

3. occrae/network/efficient_transformer.py — rename H,W→N,K + native-K camera-embed

(a) Rename — behavior-preserving relabel of the main-latent spatial axes only:

  • Do NOT rename: the public kwarg ref_spatial_size; the flat S/s sites and the whole Block/TransformerEncoder; the cross_cond image grid (interpolate_cross_pos_encoding, ch/cw, the 'b n h w d → …' rearrange at 451 where n=slot, h,w=image grid); the __main__ self-test.
(b) Native-K camera-embed (395-399) — required by camera_embed=true at K=32: 
# before
assert S <= self.max_cameras, ...
cam_idx = torch.arange(S, device=x.device)

# after — camera = s // K; K delta tokens of a camera share its embedding,
# per-delta-token identity carried by spatial_pos (ref=(1,K))
assert n_p <= self.max_cameras, f"camera embed supports <= {self.max_cameras} cameras, got {n_p}"
cam_idx = torch.arange(S, device=x.device) // k_p    # slot s = n*K + k  →  camera n
Backward-compatible: at K=1, k_p==1 ⇒ arange(S)//1 == arange(S) and n_p == S — identical to today. camera_rope was initially left un-reworked (disallowed in global mode, guarded when K>1); the review round made it native-K too (per-camera cos/sin then repeat_interleave(k_p)) and removed the guard — see Code review below.

Code review — findings & fixes xhigh · 10 finder angles

A multi-agent review swept the working tree. Five independent correctness angles each traced the K axis end-to-end and two empirically verified the bicubic size-1 replication: the production K=32 path is correct — no shipping bug. The findings were latent cross-consumer risks, one drifted duplication, and stale docs. The fixes below are numerically inert for the run (proj=1, global, camera_embed, camera_rope off, fixed_noise_mode=none) — hardening + cleanup only.
