Three jobs. Step 1 resumes the existing arm (no file edit). Steps 2 and 3 both start from its `epoch_100.pth` and
run at the same time. `freeze_except_decoder` keeps `z` bit-identical, so the flow trained on the step-1 ckpt
stays valid for the step-2 decoder.

**Finetune objective: noise-only, parity with ft10 `BSC:45421190`.** Both hops and the compose sum are decoded from
`z + σ·ε` only, with no clean term. That needs one new knob, `training.clean_decode_weight` (§1, §2). At its default
1.0 the finetune loss would equal step 1's decoder loss term for term, because step 1 already trains the detached
noised decode.
