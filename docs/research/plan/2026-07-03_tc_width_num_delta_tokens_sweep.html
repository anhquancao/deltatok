DeltaTok — num_delta_tokens (compression rate) sweep

Making the delta-token bottleneck configurable and sweeping it. Living tracker.

Started 2026-07-03 Branch revert Cluster Jean Zay H100 · zuw@h100 · qos_gpu_h100-t3 Commits 46f83cf, a343cba

Problem

The DeltaTok tokenizer compressed each consecutive frame pair (t, t+1), per camera, into a single learned delta token — hardcoded as nn.Embedding(1, hidden) and a length-1 prefix through every encode/decode block. At full res a camera has P ≈ 37×21 = 777 patches, so 1 token is a ~777:1 bottleneck — too aggressive, capping reconstruction fidelity. Goal: make the token count (a "compression rate") a config knob and sweep it.

Change (tokenizer)

New knob model.deltatok.num_delta_tokens = K (default 1 → unchanged behavior). K learned latent queries per camera per transition; compression ≈ P/K.

Deferred — flow trainer (K>1)

Scope so far is tokenizer only. Running flow matching on a K>1 tokenizer is not yet supported; the K==1 squeeze in _encode_pair_deltas keeps existing 1-token flow runs working. Before flow on K>1, update occrae/deltatok_flow_trainer.py:

  • x_spatial = z.permute(0,3,1,2).unsqueeze(-1) → (B,C,T-1,N,K) (permute 0,4,1,2,3, drop unsqueeze); z_hat keep K axis.
  • flow Transformer ref_spatial_size=(1,1) → cover K positions (e.g. (1,K)).
  • n_ctx is along the T-1 axis — unaffected by K.
