The per-channel std ratio goes the "wrong" way and should be ignored. It measures axis-aligned spread, and neither arm has any reason to align its variance with the canonical basis. The eigenspectrum is the basis-free measurement, and it is unambiguous. The two disagreeing here costs nothing — but it is why the offline script reports both.

SIGReg hit its scale target as well as its shape target: row mean-square 1.0083 and largest channel mean 0.0399 is N(0, I) to two decimals, which is exactly what the loss asks for. Relevant downstream — the flow model adds isotropic noise, so the baseline's z would need whitening first, and this one arguably would not.

How it was measured

compute_deltatok_z_spread.py builds the frozen OccRAE plus one DeltaTok module per checkpoint, runs the OccRAE encode once per batch, and encodes those identical features with every arm — so the arms are paired by construction and the data is not a variable.

Write zi for the i-th of n=203 520 delta-token rows, each in ℝC with C=768.

Covariance — accumulated exactly, in float64
Σ= 1n ∑i=1n zizi⊤ −z¯z¯⊤ , z¯= 1n ∑i=1n zi float64 because that subtraction cancels catastrophically in fp32 once z drifts off unit scale, as the baseline does (row mean-square 108).
Spectrum and variance shares
λ1≥⋯≥ λC≥0 eigenvalues ofΣ , pi= λi ∑jλj Variance along the principal axes — the rotation-invariant view, where per-channel std is not (nothing aligns the code with the canonical basis).
Participation ratio — ZPartRank
PR= (∑iλi)2 ∑iλi2 = 1 ∑ipi2 The inverse Herfindahl index of the spectrum. Squaring makes it dominated by the strongest axes.
Entropy rank — ZEntRank
ER=exp (− ∑i pilogpi ) The spectrum's perplexity: same range and endpoints as PR, but it credits a long weak tail more — so PR moving alone means only the top of the spectrum flattened.
Dimensions for 90% / 99% — ZN90
nq= mink {k: ∑i=1k pi≥q } ,q∈ {0.90,0.99}
Endpoints, and the ceiling you can actually observe
1≤PR,ER≤C , both=Ciff λ1=⋯= λC PR(N(0,I)) ≈ C1+γ , γ=Cn =0.0038 ⟹ ≈765 Both maxima are the uniform-spectrum case, and both equal C there by construction: with every pi=1/C, entropy takes its maximum H=logC so ER=elogC=C, and ∑ipi2=1/C so PR=C. Both read as "how many axes are effectively in play". A perfectly isotropic code measures ~765, not 768: even a true N(0, I) sample has Marchenko–Pastur spread from finite sampling. Not binding at 173, but it is why the rows < C guard exists — at n≈C the ceiling falls to ≈ C/2 and the metric stops describing the code at all.

Every quantity above is invariant to an overall rescale of z, which is what makes them comparable across two arms whose absolute scale is free.

Both checkpoints loaded key-exact against one shared architecture spec, so no bottleneck projection was silently left random — that failure would have looked exactly like a spread difference.

What this does and does not show

  • It measures the code, not whether the code is better. The Eval/Loss gap already on record (0.03346 vs 0.04989) is the evidence that the spread buys reconstruction quality; this explains the mechanism.
  • The "rank ~290" framing is dead. top290 = 1.000 for both arms, and the baseline is far worse than 290 — it collapses to ~50 effective dims. Stop using 290 as the reference point.
  • No seed replicate exists, so there is no measured run-to-run noise floor. A ~10× gap is far outside anything plausible as noise, but a small gap in a future comparison would not be interpretable.
  • z is encoded in bf16 (the training dtype), so the smallest eigenvalues sit on a quantization floor. The effective ranks are driven by the top of the spectrum and are unaffected; l_min is not meaningful. --cfg training.dtype=float32 removes the floor.
  • Measured on the train distribution — the one SIGReg regularized. --split val checks drift.

Reproducing, and the live metric

Offline, on one H100 (~8 min at 100 batches):

srun -A zuw@h100 -C h100 --qos=qos_gpu_h100-dev --gres=gpu:1 --cpus-per-task=24 \
  --time=01:00:00 bash -lc 'cd $TRG_WORK/code/deltatok && source env_jz_h100.sh && \
    python compute_deltatok_z_spread.py --num_batches 100'
# other arms:  --ckpt label=/path/to/ckpt   (repeatable)

The same measurement now also runs during training, once per eval loader, via training.eval_z_spread. Both paths call the same occrae/z_spread.py (ZSpreadStats), so an offline number and a TensorBoard number for one checkpoint cannot disagree. It logs under Eval/<test_name>/: ZPartRank, ZEntRank, ZN90, ZTop1Share, ZTotalVar, ZRowMeanSquare, ZMeanAbsMax. A fixed val set makes these comparable across epochs and runs, and they are collected with or without SIGReg — which is what lets a sigreg arm and its plain twin be compared at all.
