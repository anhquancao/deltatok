Why ..._50k_whitenpos doesn't work — recipe audit vs VGGT-World & RAE

Per-slot whitening is correctly implemented and RAE-faithful — and it changed nothing, because whitening was never the bottleneck. Auditing the run against two working flow-on-frozen-latents recipes (third_party/VGGT-World, third_party/RAE) finds one structural rule both satisfy and this run violates: the flow ViT is narrower than the latent (1152 < 1536).

TL;DR

  • Not a bug. The per-slot (K, C) whitening pair (occrae/deltatok_shared.py) is shape-asserted, std-floored, exactly inverse, and MSEToken stays in raw z-space. The failure is the recipe, not the wiring.
  • Root cause (primary): vit_size=xlarge → hidden 1152 < latent C=1536. The in_proj is a lossy 0.75× compression of both signal and noise. VGGT-World sets model width == latent dim (1024, no input projection); RAE's central claim is width > latent dim (1152 for 768-d latents + a 2048-wide DDT head). Under-width is RAE's textbook signature: teacher-forced loss drops, samples stay at mean + noise.
  • Missing secondaries (both references use all three): timestep shift toward noise (RAE α≈6.93 @ 196k dims; ours: none at ~393k scalars), EMA for sampling (use_ema: false), zero-init of the output projection (ours is xavier).
  • Whitening verdict: not necessary (VGGT-World trains on raw tokens) and not sufficient (this run). Keep it, but stop expecting it to move MSEToken.

Why width < latent dim fits the failure signature

  • Teacher-forced denoising survives compression: at any t > 0, z_t still contains an x-leak, so reconstructing x through a 1152-d bottleneck stays easy — the train loss keeps falling.
  • Generation does not: transporting an isotropic 1536-d Gaussian onto the latent manifold needs a velocity field the 1152-d trunk cannot represent. The 384 lost input/noise dimensions are unrecoverable at exactly t≈0, where the sampler starts and where all information must come through the network.
  • That is precisely "loss goes down, samples stay at mean + noise" — RAE reports a hard capability cliff when DiT width drops below the token dim, and VGGT-World implicitly agrees by not even allowing themselves a projection layer.
  • The whitening result is consistent: VGGT-World proves whitening is not necessary (raw tokens work when width == dim); this run proves it is not sufficient. The Phase-0 gate already hinted at it — 9.2× std ratio, "ambiguous", 78.7% of the energy a single constant channel (c=527) that any network absorbs as a bias within steps.

Metric note — MSEToken cannot show generative progress

MSEToken is minimized by conditional-mean prediction. A perfect sampler drawing from p(z | context) scores ≈ 2× the conditional variance — i.e. it can look worse than a collapsed model. A flat MSEToken therefore cannot distinguish "no progress" from "more honest sampling". The readouts that can move: the rescaled-LossFlow gate (4.70× conversion, prior journal) and the decode metrics (LossDepth/LossPointmap vs their *_tok ceilings).

Recommended fixes, ranked

  1. primary model.vit_size=xxlarge (1536 wide, 28 deep): width == C, the VGGT-World configuration. The sequence is tiny (4 transitions × 64 tokens + context), so the width is affordable. RAE-style alternative: keep the trunk, add a 2048-wide × 2-block DDT head.
  2. Timestep shift — the prior journal's "adjacent lever, not started". One config key: sweep model.mu ∈ {−1.8, −2.3, −3.3} (σ=1.4 kept), matching the documented α ≈ 3.5–14 ambiguity. RAE applies the same shift to the 50-step Euler grid — ours should too.
  3. EMA on (0.9995–0.9999), eval with EMA — knob #1 from the collapse doc, still off. Also removes the eval bounce that makes MSEToken hard to read.
  4. Zero-init out_proj — one line in initialize_weights (efficient_transformer.py:271); both references zero the output path.
  5. Keep whitening (pooled ≈ pos ≈ baseline in the ablation; either is fine), and read progress from decode metrics / rescaled LossFlow, not MSEToken.

If a width-1536 run still walls at mean + noise, the next structural difference to copy from VGGT-World is in-context conditioning (frame-0 tokens concatenated into the joint attention sequence instead of cross-attn) — but wait for the width result first: it is the only hard violation of both working recipes.
