Evaluation sets — all-data ctx2fwd8 forecasting benchmark · as used since 2026-09-30

Three driving test sets, 6,413 windows: 2 frames in, the next 8 out, 0.5 s apart

Every window is 10 consecutive front-camera frames spanning 4.5 s. The model sees frames 0–1 and forecasts frames 2–9, up to 4 s ahead. Scoring uses each frame's LiDAR depth and its pose, both in metric units, with no fit or alignment.

KITTI odometry · seq 08

nuScenes · val split

2,018 windows
202 segments, a start every 16 frames (1.6 s). Same sensor as training, disjoint segments.
Sized so the set, not the sample, limits the error. At ~2,000 windows the standard error of the mean is 1.5–3.0% of the mean and within 0.2 pp of the full split; KITTI cannot go below ~2.2% because it is one drive.

Window selection — deterministic · no random subset

Every window that fits is built, then thinned within each scene; the whole thinned split is scored

Windows per set · all start frames vs scored
window_stride 2 within one scene · each bar is one 10-frame window
  • 1 · Build. A window starts at every frame whose 10 slots all exist (exact_len / fs1 pkls), so windows overlap by up to 9 frames.
  • 2 · Thin. Inside each scene, keep a window only if it starts at least window_stride frame ids after the last kept one (base_seq_dataset.py:127-137).
  • 3 · Score all. Evals pass --num_items 1000000, above any split, so nothing is subsampled. The loader's fixed permutation (seed 777) only sets the order.
  • 4 · Same for every model. DeltaTok, VGGT-World and Gen3R dump window n in loader order; the scorer checks names and masks match before scoring.
Overlap is kept on purpose. At stride 2 neighbouring windows share frames, but the standard error is computed with block bootstrap over shared frames, so it is not overstated (slide 5).

Data hygiene — what was fixed, and what numbers it invalidates

Eval numbers before 2026-09-30 are not comparable on KITTI or nuScenes

nuScenes rebuilt

The first 8 val scenes mixed ~12 Hz sweeps into the 2 Hz keyframes

scene-0003 and scene-0012 to 0018 in the old occ3d_nuscenes_processed folder. The val split was rebuilt from keyframes only as occ3d_nuscenes_val_preprocessed (BSC). Windows in those scenes had the wrong time step.

Window draw changed

Thinning by window_stride replaced a capped random draw

KITTI and nuScenes windows were re-drawn on 2026-09-30, so earlier scores came from different windows.

Checks in place
  • Same pkls on both clusters. KITTI and nuScenes val pkls md5-match between Jean Zay and BSC.
  • Same windows for every model. The scorer asserts scene and frame names and the GT mask of each dumped window.
  • One GPU per eval. The eval RNG is seeded per rank, so only same-GPU-count runs are compared.
  • No alignment. Depth, points and poses are scored at metric scale; nothing is fitted to GT.

Draft: evaluation protocol paragraph

We evaluate on three driving datasets: KITTI odometry sequence 08, the nuScenes validation split (150 scenes) and the Waymo Open validation split (202 segments), which we hold out as a test set. Each sample is a window of 10 front-camera frames spaced 0.5 s apart (4.5 s); models observe the first two frames and forecast the remaining eight, 0.5 to 4 s ahead. We build a window at every valid start frame and keep, within each scene, windows that start at least 2 frames (KITTI, nuScenes) or 16 frames (Waymo) apart, yielding 2,013, 2,382 and 2,018 windows. At these sizes the standard error of the mean, from a block bootstrap over windows that share frames, is 1.5–3.0% of the mean. Depth is scored against projected LiDAR within 50 m and camera poses against the dataset poses, at metric scale and without alignment. No real KITTI or nuScenes data is used to train our model.
Before it goes in
  • "No real KITTI or nuScenes" holds for our flow model; check DA3, the tokenizer and the baselines (slide 6).
  • Native image sizes are dataset specs; the KITTI preprocessing script is not in the repo.
  • KITTI is one drive. Say so, or add more odometry sequences.
  • SE is a lower bound. Only frame sharing is modelled, not slower structure along a drive.
