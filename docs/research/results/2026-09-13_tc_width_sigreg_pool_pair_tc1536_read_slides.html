verdict — what the pool pair settles

The pool frees the code. Recon did not need it freed.

The 09-11 read named two suspects for the stuck tc1536 code: SIGReg's sensitivity at a small pool, and the weight. This pair answers the first and narrows the second.

1
The pool is the lever for rank. Pool 24576 leaves ZPartRank 1.0 at ep 6 and ends at 15.9% / 22.9% of Cz, with train ZRowMeanSquare 1.11. No bottleneck, no norm on z.
2
Cutting the weight to 0.02 did not free the code. Pool 8192 at 0.02 enters rank 1.0 at ep 4 and stays there to ep 31, like the 0.06 control.
3
The stuck code is the better code for recon. Pool 8192 is −11.1% / −16.5% under the control, and +57.7% over no SIGReg on KITTI. Pool 24576 is +16.0% / +19.2% over pool 8192. ZPartRank 1.0 is a tail statistic; it does not measure what the decoder uses.
4
No stall. The 2026-07-31 pool failure did not reproduce at scale 33.0 with sw0. The cost is ~3 epochs of delay and a higher plateau.
open question

Which code does the flow want?

The token loss prefers pool 8192. A flow model over a code with RMS 872 carried by a sparse tail is a different problem than one over unit-scale z. Only a flow read can pick between them.
