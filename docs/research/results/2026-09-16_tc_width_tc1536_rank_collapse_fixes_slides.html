the mechanism — an attention sink in an unnormalised residual stream

One delta slot becomes a massive activation in encoder block 0. Nothing normalises it, and SIGReg cannot see it.

In the stuck pool-8192 arm, slot k = 44 is the tail in all 160 val sequences. It holds 99.5–99.8% of z's variance. Remove it and the same code has rank 244–278.

why the norms do not stop it · DINOv3ViTLayer, pre-norm
h = h + ls1 · Attn(LN1(h))    # LN sees the branch input only
h = h + ls2 · MLP(LN2(h))     # the residual h is never normalised
z = h_last[:, :, :K]          # tc1536: no LN, no projection
  • Born in block 0. The slot reads ~4200 after block 0 and stays roughly flat through block 11.
  • Always the same slot, always positive. 160 of 160 sequences have exactly one tail token, k=44.
  • SIGReg cannot pull it back. A tail of fraction 1.6% costs 3e-4 to 6e-4. The restoring force peaks near |z| ≈ 100, turns negative by ~1000, and is noise at 1e4. The live tail sits at 2000–7000.
  • Pool size moves the estimator floor, not the mean force. Arms that recovered blew up broadly first (SIGReg stat ≥ 0.2), which gives SIGReg a whole-batch signal.

fix 1 — SIGReg weight and SIGReg pool, no change to the network

A 3× weight keeps the sink. A 3× pool frees the code, on one seed, for +16–19% recon.

Weight 0.06 (with warmup 2000) stays at rank 1.0 through ep 32. Pool 24576 leaves 1.0 at ep 6 and ends at 245 / 352 dims (KITTI / nuScenes). At ep 31 it costs +16.0% KITTI and +19.2% nuScenes LossRecon against the unfixed arm. The census says recovery is not predictable, so one seed is thin.

fix 2 — 4 register slots, a free home for the sink · interim, ep 45

Register slots do not take the sink. It stays in the delta slots, and the arm never trains.

verdict — questions 14, 15, 16

Free the code with the SIGReg pool if it replicates. The LayerNorm bottleneck is the reliable fallback, at 2.3× the recon.

The collapse comes from the architecture, an unnormalised pre-norm residual, and SIGReg's blind spot for a sparse tail. The fixes act on one or the other.

1
Estimator side: the pool works, the weight does not. Pool 24576 reaches rank 245 for +16–19% recon. Weight 0.06 stays at 1.0. One seed each, and recovery is not predictable from the knobs.
2
Registers fail. The sink stays in the delta slots (11k vs 77), rank stays at most 1.3 from ep 9, and recon sits at the copy level through ep 45.
3
Normalising z works, if SIGReg is ramped. No bottleneck arm ever blew up. At warmup 0 it stalls; at warmup 2000 it trains, at 2.3× the pool arm's recon and rank ~63–75.
4
Rank 1 is not a recon problem. The unfixed arm has the best loss. Only a downstream read can say what freeing the code is worth.
