what this does and does not establish

Verify the tc512 anomaly before building anything on it.

solid
  • Plain improves with width. Monotone at every epoch, three widths, no crossover.
  • Compose does not. Its optimum is tc128; it is worse than plain at every shared width.
  • Rank tracks recon in both families (r ≈ −0.97), and plain converts width into rank while compose does not.
not established
  • One seed per cell. No error bars anywhere on this deck.
  • tc512 compose is off-trend against tc768. Most likely a bad run, and it is doing a lot of work in the headline numbers.
  • tc768 plain has no recon logged — that run predates the stdout line, so the plain curve is three points, not four.
  • Why compose fails to convert width into rank is open. Summing two codes concentrates variance, but the static arithmetic accounts for only −11% to −28%, not −72%.
next, in order
  • 1 · Re-run tc512 compose on a new seed. Everything else waits on this. If it lands near tc768's 0.0478 there was never a wide-tc regression.
  • 2 · Warm-start compose from the plain tokenizer. INIT_CKPT is already wired in the slurm script and epoch_50.pth of the plain tc512 arm exists. Compose collapses rank from epoch 4 — hand it a high-rank code instead of asking it to find one.
  • 3 · Lower compose_weight to 0.25 / 0.5 at tc512. Already an env knob.
  • 4 · Not the sigreg weight. The tc768 plain ladder runs rank 135 → 98 → 48 as sigreg goes 0.005 → 0.01 → 0.05. Wrong lever.
practical read
  • Need reconstruction only → go wide, skip compose. tc512 plain, 0.0343.
  • Need composability → stay near tc128 until the objective is fixed. Compose buys 3.4× on LossRecon_Comp and that is what it is for.
